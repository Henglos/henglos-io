---
title: Pair a driver
description: Connect the computer your board is plugged into.
---

The **driver** (`hio driver`, part of the Henglos IO CLI) is a small daemon that runs on the computer your board is plugged into. It
keeps a connection to your hosting, builds what the board needs for a workflow, and talks to the
board over its USB REPL. A driver can serve several boards, and you can pair as many drivers as you
have benches.

## Pair it

<Steps>
<Step>

### Point it at your hosting

```bash
hio driver configure https://hio.localhost
```

</Step>
<Step>

### Log in with a pair token

In the studio, open **Drivers** and create a pair token, then:

```bash
hio driver login <pair-token> "My bench"
```

The name is how the driver shows up in the studio.

</Step>
<Step>

### Start it

```bash
hio driver start
```

It runs in the background. `hio driver status` shows whether it's up, `hio driver stop` stops it.
`hio driver start --mode run` keeps it in the foreground with its logs — handy when something's off.

</Step>
</Steps>

Once it's connected, it appears in the studio's driver selector with the serial ports it sees.

## Talking to the board

The driver opens the board's port, interrupts whatever `main.py` is doing and enters MicroPython's
raw REPL — the same mechanism `mpremote` uses — so no extra firmware or wiring is needed. When it's
done, it soft-resets the board, and the uploaded program starts on its own again.

<Callout title="One task per port">
  A port serves one thing at a time — an upload, an execution or a debug session. Starting another
  while one runs fails with `resource_busy`; stop the first one.
</Callout>
