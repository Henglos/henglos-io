## What it offers

| | |
| --- | --- |
| **Capabilities** | `wifi`, `bluetooth` — so WiFi and HTTP run on it. |
| **Firmware** | MicroPython 1.29.0 (`ESP32_GENERIC`), flashed at `0x1000`. |
| **Connection** | USB serial, at 115200 baud by default (up to 921600). |

## Pins worth knowing

- **Analog in** reads 0–3.3 V. The ones on ADC2 (GPIO0, 2, 4, 12–15, 25–27) can't be read while
  Wi-Fi is on — use GPIO32–39 for a sensor in a workflow that connects.
- **GPIO34–39** are input only: no output, no pull-up or pull-down.
- **GPIO0, 2, 12 and 15** are read at boot to pick how it starts — something pulling them the wrong
  way can keep the board from booting.
- **GPIO1 and 3** are the USB serial the studio talks over — leave them free.

## Flashing it

**Compile + Flash** in the studio's board settings builds this board's MicroPython with the
platform's runtime frozen in and writes it over USB — once per board, and again when the workflow's
platform version changes. See [Building a board](/docs/packages/building-a-board#flashing-the-firmware).
